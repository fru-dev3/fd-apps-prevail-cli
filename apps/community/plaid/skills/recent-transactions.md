# Recent transactions

Pull every transaction Plaid has added since the last sync, across all accounts
linked to `PLAID_ACCESS_TOKEN`, and append them as JSONL to
`data/transactions/recent.jsonl`.

This is a real fetch: the api runner POSTs to Plaid's `/transactions/sync`
endpoint with the stored credentials. Nothing here is generated by a model.

How the cursor works:

- The first run sends `"cursor": ""`, which Plaid treats as "from the
  beginning": the full history of the item, paged 500 at a time.
- Plaid answers with `added`, `modified`, `removed`, `next_cursor` and
  `has_more`. The runner keeps requesting while `has_more` is true, feeding
  `next_cursor` back into the body each page (`paginate_while` / `cursor_path`).
- The final `next_cursor` is persisted by the sync daemon in `sync-state.json`,
  so the next refresh only fetches what changed since.

What is written: each object in `added` (one JSON object per line), across all
pages, as Plaid returns it (`date`, `amount`, `name`, `merchant_name`,
`personal_finance_category`, `account_id`, `transaction_id`, ...). `modified`
and `removed` are not folded in yet; the file is an append-only ledger of
additions.

The run summary routed to the wealth, tax and business domains is the item
count and page count, for example `43 items across 1 page`.
